01 GUÍA PRÁCTICA & TEMPLATES

Ingeniería de Prompts Profesional: Del Lenguaje a la Creación

Un prompt profesional no es una pregunta al azar: es un contrato de especificación de software ejecutable. Debe delimitar el contexto, imponer restricciones negativas, estructurar la salida y minimizar la entropía probabilística del modelo.

* El Framework R-T-C-F (Rol, Tarea, Contexto, Formato)

(1) Rol y Especialidad: Define la identidad técnica del modelo. (2) Tarea Delimitada: Qué acción exacta e indivisible debe resolver. (3) Contexto y Restricciones: Supuestos permitidos y directivas negativas explícitas. (4) Formato y Tokens de Salida: Estructura (JSON, Markdown, esquemas validados).

Prompt Ejecutivo // Pitch Deck para Inversionistas 
Actúa como un Consultor Estratégico de McKinsey y diseñador de pitch decks. 
Crea la estructura para una presentación ejecutiva de 6 diapositivas en formato Markdown para importar en Gamma/Beautiful.ai.
Tema: "Migración de Arquitectura Monolítica a Microservicios con Edge Computing y Base de Datos Vectorial para IA".
Audiencia: CTO y Junta Directiva. Tono: Conciso, de alto impacto financiero y técnico.

Reglas por Diapositiva:
- 1 Título contundente (máximo 6 palabras).
- 1 Declaración clave (Key Takeaway) en negrita.
- Disposición en 3 columnas o tarjeta de métricas numéricas (e.g., Latencia -45%, Disponibilidad 99.99%).
- Máximo 35 palabras por slide. Cero párrafos largos; utiliza bullet points con verbos de acción.
- Sugiere un prompt de generación de imagen conceptual minimalista en dark-mode para cada diapositiva.
Software Engineering

1.3 Desarrollo de Software con Contratos (Cursor, Claude 3.5, Copilot)

En ingeniería de software aplicamos Contract-Driven Prompting: tipado estricto en tiempo de ejecución (Zod), manejo tipado de errores (Result Types) y pruebas unitarias de concurrencia.

Prompt de Arquitectura // TypeScript, Fastify & PostgreSQL 
Eres un Arquitecto de Software Principal especializado en arquitecturas limpias y sistemas de alto rendimiento en TypeScript y Node.js.
Tarea: Diseña e implementa el módulo de gestión de transacciones concurrentes con bloqueo optimista para un servicio de pasarela de pagos.

Requisitos estrictos de implementación:
1. Define primero las interfaces y tipos inmutables (Zod schemas para validación de entrada en tiempo de ejecución).
2. Manejo exhaustivo de errores tipados mediante un Result Type (Ok / Err) sin lanzar excepciones no controladas.
3. Conexión a base de datos usando transacciones atómicas con aislamiento Serializable.
4. Código modular: separa controlador, servicio y repositorio desacoplado.
5. Incluye 3 pruebas unitarias con Vitest/Jest simulando condición de carrera (race conditions).
6. Restricciones: No utilices dependencias externas obsoletas; código limpio sin comentarios obvios; documenta únicamente la complejidad algorítmica Big-O en JSDoc.

Bases de Datos, Buses de E/S y Deep Learning

3.2 Entradas y Salidas (E/S - I/O) y Jerarquía de Latencia

La CPU opera en nanosegundos; la red opera en milisegundos. Esta disparidad física exige arquitecturas no bloqueantes basadas en eventos (`epoll`, `async/await`) y streaming de tokens.

3.3 Machine Learning Tradicional vs Deep Learning

La frontera matemática: el ML tradicional depende de la extracción manual de características (*Feature Engineering*), mientras que el Deep Learning extrae representaciones jerárquicas autónomamente mediante capas neuronales profundas y mecanismos de autoatención.

Figura 3.3 // Redes Transformer: paralelización masiva de autoatención en clusters de aceleración tensorial.
Criterio Técnico Machine Learning Clásico Deep Learning Moderno

Escalabilidad con datos Alcanza meseta con volúmenes medianos. Mejora continua con leyes de escala (Scaling Laws).
Hardware requerido CPUs convencionales. GPUs / TPUs de cómputo tensorial masivo.
